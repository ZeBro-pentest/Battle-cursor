## Сессия 3 — Модели, логика монет, исправление race condition

### 1. Ревью всех Django моделей

Выявлены расхождения с ERD в [[Diagrams/Diagrams.drawio]]:

- `Cursor.debuffs` — в диаграмме опечатка `debufs`
- `Score.image_url` и `User.profile_drawing` — отсутствовали в ERD
- `Server.status` и `Server.game_id` — реально существуют (убирать из ERD не нужно)

### 2. Анализ логики монет
Проверены `backend/game/services.py` и `backend/ai/tasks.py`.

**Поток монет:**
```
grade_round → coins_earned = score × 10 → Redis накапливает
game_over → sync_coins_from_redis → User.coins += redis_coins
          → winner (max coins) → User.rating += 1
          → on_commit: cache.delete_many(coin_keys)
```

**Найдены два бага:**

#### Баг 1 — Redis внутри transaction.atomic() (задокументирован, не исправлен)
`cache.set(coin_key, ...)` вызывается внутри `with transaction.atomic()` в `grade_round`.
Если DB rollback — Redis уже обновлён. При retry (max_retries=3) монеты задвоятся.
Файл: `backend/ai/tasks.py:205–208`

#### Баг 2 — Race condition: delete_game vs cleanup_drawings (ИСПРАВЛЕН)
Оба таска имели `countdown=60`. `delete_game` каскадно удаляет Round,
`cleanup_drawings` ищет Round.objects.filter(game_id) — мог не найти раунды.

### Изменения в коде — `backend/ai/tasks.py`, фикс countdown
```python
# было:
transaction.on_commit(lambda: delete_game.apply_async(args=[game_id], countdown=60))
cleanup_drawings.apply_async(args=[game_id], countdown=60)

# стало:
transaction.on_commit(lambda: delete_game.apply_async(args=[game_id], countdown=120))
cleanup_drawings.apply_async(args=[game_id], countdown=30)
```

Новый порядок: `cleanup_drawings` (t+30s) → `delete_game` (t+120s), 90s запаса.

### Решения принятые
- `Server.status` и `Server.game_id` остаются в ERD (они реально есть в коде)
- Баг с Redis внутри транзакции — не фиксим сейчас (не критично для MVP, нужен рефактор)
- Winner при ничьей — первый в итерации, приемлемо для MVP
